# fair-bioheaders-tools-capi (`libfhcore`, `fhcore.h`)

The C ABI of the FAIR-bioHeaders engine for the Julia (`@ccall`) and Perl
(FFI::Platypus) wrappers (Tools#207 section 3, decisions 7, 8 and 14).
ABI version 0.1: while the ABI is `0.x`, wrappers require an exact
major.minor match (`fh_abi_major`, `fh_abi_minor`).

`include/fhcore.h` is generated by `cbindgen --config cbindgen.toml --crate
fair-bioheaders-tools-capi --output include/fhcore.h`; CI regenerates it and fails
on any difference. The Linux shared library has SONAME `libfhcore.so.0`.

## Rules

- Only opaque handles, fixed-width integers, `double` and pointers cross the
  boundary. Every byte string has an explicit length; outputs also carry a
  trailing NUL that is not counted, and may contain U+0000.
- Outputs are borrowed from the handle that produced them until its release
  function runs. Each handle type has exactly one release function, and each
  accepts NULL. Never free engine memory with another allocator.
- A verdict (invalid, unsupported, limit) is `FH_OK` with a result; return
  codes are call failures. There is no thread-local "last error".
- Engines and results are immutable and may be shared across threads. A
  stream may move between threads but must not be fed concurrently;
  `fh_stream_cancel` is safe from any thread.

## Panic containment and its limits

Every entry point runs inside `catch_unwind` and returns `FH_E_INTERNAL` with
the panic message in an owned `fh_error`; a stream that panicked returns
`FH_E_STATE` afterwards. The library must be built with `panic = "unwind"`.

**Not contained**: `panic = "abort"` builds; a panic while already panicking; a
panic in `Drop` during unwinding; allocation failure (Rust aborts); stack
overflow; `abort` inside a dependency; and memory corruption caused by a host
that violates the pointer, length or ownership rules. Input-sized allocations
are bounded by the engine limits before they are made, and YAML/JSON nesting is
depth-checked before recursion.

The `fault-injection` feature adds `fh_test_panic` for wrapper tests. It is
never enabled in release artifacts.
